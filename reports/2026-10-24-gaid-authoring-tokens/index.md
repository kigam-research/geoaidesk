# Workflow 저작 토큰 사용량을 CLI와 비교하고 줄임

## 0. 한눈에

| | |
|---|---|
| 요청 | Workflow를 만들 때 GAID가 쓰는 토큰이, CLI에 논문을 주고 이해시켜 작업할 때보다 많은지 확인 |
| 결론 | 크게 많지 않았습니다. 고치기 전 GAID는 Codex CLI보다 정가 기준 23% 비쌌고 Claude Code의 3분의 1 이하였습니다. 캐시를 쓰도록 고친 뒤에는 정가 $0.50으로 Codex CLI보다 쌉니다. |
| 믿을 수 있는 정도 | 논문 1편으로 방식마다 한 번씩 돌린 결과입니다. 같은 실행을 반복했을 때의 흔들림은 재지 않았습니다. Claude Code는 다른 모델(Claude Opus 5.5)입니다. |
| 결정할 일 | 없음 |

## 1. 요청한 것

> 그리고 워크플로우 생성을 위해 에이전트 토큰이 많이 소요되는것이 맞나? 보통 cli에 논문을 주고 이해하고 작업하는 토큰이랑 비슷한수준이면 많은 소비량이 아닐수 있다. 이점은 점검할 필요가 있다. — 2026-10-24 요청

완료 기준: 같은 논문으로 같은 결과물(Workflow 초안 하나, 질문에는 같은 답)을 만들게 하고, GAID 허브 저작과 Claude Code CLI·Codex CLI의 입력·캐시·출력 토큰과 정가를 비교합니다. GAID가 확실히 비싸면 원인을 줄이고 다시 잽니다.

## 2. 수행한 것

1. 검토 앱과 따로 떨어진 측정용 GAID를 띄웠습니다. 저작 저장소, 허브, 서재, 프로젝트는 모두 측정 폴더에 두고 모델 로그인만 검토 앱 것을 썼습니다(사용자 결정, 10-24).
2. 서재 미리보기용 원고(36쪽, 약 10만 자)를 출처로 넣고 분석 → 질문 답변 → 초안 순서로 GAID 허브 저작을 끝까지 돌렸습니다. 모델은 GPT-6.1 Sol, 추론 수준은 높음입니다. 질문은 모델이 권한 답, 없으면 첫 선택지로 답했습니다.
3. 같은 원고와 GAID의 초안 지시문 전체, 같은 답, 같은 어휘 목록을 과제 파일로 만들었습니다. 이를 Codex CLI(GPT-6.1 Sol, 높음)와 Claude Code(Claude Opus 5.5)에 주고 "논문을 읽고 이해한 뒤 Workflow 초안을 써라"라고 시켰습니다. CLI는 PDF를 직접 읽습니다.
4. GAID 호출 기록을 호출마다 나눠 어느 단계가 얼마를 쓰는지 보았습니다.
5. 원인 두 가지를 고치고 같은 원고, 같은 답으로 GAID를 다시 돌렸습니다.

## 3. 결과

그림 없음: 수치 비교라 표로 충분합니다.

표 1. 같은 원고로 Workflow 초안 하나를 만들 때의 토큰과 정가

| 방식 | 모델 | 입력 토큰 | 그중 캐시 | 출력 토큰 | 정가 | 걸린 시간 |
|---|---|---:|---:|---:|---:|---:|
| GAID 허브 저작 (고치기 전) | GPT-6.1 Sol 높음 | 111,774 | 0 | 51,262 | $0.74 | 14분 |
| GAID 허브 저작 (고친 뒤) | GPT-6.1 Sol 높음 | 109,908 | 33,792 | 34,350 | $0.50 | 14분 |
| Codex CLI | GPT-6.1 Sol 높음 | 1,523,940 | 1,444,864 | 29,902 | $0.60 | 24분 |
| Claude Code | Claude Opus 5.5 | 1,203,812 | 1,070,858 | 63,281 | $2.54 | 10분 |

정가는 Pi 모델 목록의 공개 단가로 셌습니다. GPT-6.1 Sol은 100만 토큰당 입력 $2, 캐시 입력 $0.1, 출력 $10입니다. Claude Opus 5.5는 입력 $4, 캐시 읽기 $0.2, 캐시 쓰기 $5, 출력 $20이고, 그 값은 Claude Code가 보고한 금액입니다. 실제 사용은 구독이라 GAID 기록에는 $0으로 남습니다. 정가는 크기를 비교하는 데만 씁니다.

표 2. GAID 호출별 내역

| 호출 | 고치기 전 입력 / 캐시 / 출력 | 정가 | 고친 뒤 입력 / 캐시 / 출력 | 정가 |
|---|---|---:|---|---:|
| 분석 | 25,872 / 0 / 13,135 | $0.18 | 25,894 / 0 / 12,416 | $0.18 |
| 초안 첫 응답 | 34,179 / 0 / 20,084 | $0.27 | 33,969 / 0 / 18,545 | $0.25 |
| 초안 수정 (검사에서 걸린 곳 고치기) | 51,723 / 0 / 18,043 | $0.28 | 50,045 / 33,792 / 3,389 | $0.07 |

GAID는 논문 본문을 호출마다 한 번씩만 보냅니다. 그래서 읽은 입력은 Codex CLI의 7%, Claude Code의 9%입니다. CLI는 PDF를 쪽 단위로 꺼내 읽고, 도구를 부를 때마다 지금까지의 대화를 다시 보내 입력이 100만 토큰을 넘습니다. 그 대부분은 캐시에서 읽힙니다.

토큰 차이가 큰데도 비용이 비슷한 까닭은 캐시 단가입니다. 캐시 입력은 원래 값의 5%입니다. Codex CLI는 입력의 95%를 캐시에서 읽었고, 고치기 전 GAID는 하나도 읽지 못했습니다. GAID가 모델에 캐시 키를 보내지 않았기 때문입니다.

고치기 전 비용의 38%는 수정 호출에서 나왔습니다. 서버 검사에서 한 곳이 걸리면 GAID는 논문과 첫 응답을 통째로 다시 보냈고, 모델은 초안 전체(약 4만 6천 자)를 다시 썼습니다. 오류 한 줄을 고치는 데 출력 18,043 토큰이 들었습니다.

초안 하나를 쓰는 데 드는 출력은 어느 방식이든 2~6만 토큰입니다. 고친 GAID(3만 4천)와 Codex CLI(3만)는 거의 같습니다.

고친 내용:

1. 모든 저작 호출이 같은 지시문과 출처 본문으로 시작하게 순서를 바꿨습니다. 분석·초안·개정·수정 호출이 앞부분을 공유합니다. 프로젝트마다 캐시 키를 보내 모델 쪽 캐시가 그 앞부분을 다시 쓰게 했습니다.
2. 초안 수정과 개정은 바뀐 항목만 돌려받아 서버가 앞 초안 위에 덮어씁니다. 분석 수정과 처음 초안은 지금처럼 전체를 받습니다.

결과: 수정 호출의 비용이 $0.28에서 $0.07로 줄었고, 전체는 $0.74에서 $0.50으로 32% 줄었습니다. 이제 Codex CLI보다 쌉니다.

## 4. 검증

- 과학적 검증: 해당 없음. 이번 작업은 비용을 쟀고, 초안의 방법 내용이 옳은지는 보지 않았습니다. 고치기 전과 고친 뒤의 GAID 초안은 둘 다 서버 검사를 통과했습니다. 경고는 각각 2건, 1건이고 단계는 둘 다 5개입니다. CLI가 쓴 초안은 GAID 검사에 넣지 않았습니다.
- 비교 기준과 단위: 같은 원고와 같은 답, 같은 모델 계열(Codex CLI)로 쟀습니다. 토큰은 각 도구가 보고한 값이고, 정가는 위 단가로 셌습니다.
- 반복과 흔들림: 방식마다 1회입니다. 모델 응답이 매번 달라 출력 토큰은 실행마다 바뀝니다(고치기 전과 뒤의 초안 첫 응답은 20,084와 18,545). 줄어든 몫의 대부분은 수정 호출에서 나왔고, 그 차이(출력 18,043 → 3,389)는 흔들림보다 큽니다.
- 다른 설명: 캐시 적중은 모델 쪽이 보장하지 않습니다. 고친 뒤 실행에서도 분석 다음 초안 호출은 캐시에 맞지 않았습니다. 따로 짧은 시험 호출 세 번을 보냈는데, 같은 앞부분 24,861 토큰 가운데 24,704가 두 번째와 5분 뒤의 세 번째 호출에서 캐시로 읽혔습니다. 순서와 캐시 키는 제대로 작동하지만, 실제 실행에서는 맞을 때도 안 맞을 때도 있습니다.
- 소프트웨어 검증: 저작 시험 74개가 통과했습니다. 새 시험 하나는 분석과 초안의 앞부분이 같고 캐시 키가 같은지 확인합니다. 다른 하나는 수정과 개정이 바뀐 항목만 받고 나머지를 유지하는지 확인합니다. 전체 점검 결과는 부록 A에 적었습니다.

## 5. 한계

- 논문 1편, 방식마다 1회입니다. 10-23 포천 시험처럼 논문 2편과 코드, 자료 파일 10개를 넣으면 호출당 입력이 5만 토큰 안팎으로 커집니다. 그때도 같은 비율이 나오는지는 재지 않았습니다.
- 분석과 초안 사이에 연구자가 질문에 오래 답하면 모델 쪽 캐시가 사라져, 초안 첫 호출은 캐시 없이 갑니다. 이번에 줄어든 몫은 대부분 같은 작업 안의 수정 호출에서 나왔습니다.
- Claude 모델로 GAID 저작을 돌린 결과는 없습니다. Claude는 캐시 위치를 따로 지정해야 하고, GAID는 아직 그렇게 하지 않습니다.
- 구독 사용량 한도에서 캐시 입력을 어떻게 세는지는 공개되지 않아 확인하지 못했습니다.
- 서재 질문 경로(질문 하나에 90만~200만 토큰)는 이번 범위가 아닙니다.
- 검토 앱 로그인 가운데 "Sign in with ChatGPT"는 이미 만료되어 갱신이 거부됩니다. 측정은 같은 저장소의 "OpenAI Codex (legacy)" 로그인으로 했습니다. 검토 앱에서 앞의 로그인을 쓰려면 다시 로그인해야 합니다.
