# 지도 타일 표시, 배경지도 선택, Markdown 그림 경로 규칙

## 0. 한눈에

| | |
|---|---|
| 요청 | PC71에서 검토할 때 지도 확대·축소가 느린 문제와 Markdown 그림이 깨지는 문제를 고치고, 배경지도를 쓸 수 있게 합니다. |
| 결론 | 지도 방식은 조사 결과 기존 OpenLayers에 타일 방식을 더하는 안이 여전히 유력해 그대로 구현했습니다. 사용자와 같은 터널 경로에서 확대·축소 한 번의 대기가 1.5–2.4초에서 0.04초 이하로 줄었고, 배경지도는 없음(기본)과 온라인 지도를 모두 고를 수 있습니다. Markdown 그림 규칙은 모든 에이전트 지침과 파일 저장 직후 자동 검사로 넣었습니다. |
| 믿을 수 있는 정도 | 실제 표본 자료 3종과 합성 자료로 브라우저에서 측정했습니다. 사람이 직접 PC71 화면에서 쓴 체감, 배경지도 제공 기관의 프록시·캐시 허용 여부는 확인하지 못했습니다. |
| 결정할 일 | 없음 |

## 1. 요청한 것

> "첨부한 이미지 처럼 현재 71PC에서 검토중인데 md 파일에서 그림이 깨져서 보인다. 그리고 두번째 첨부한 이미지처럼 tif, shp를 비롯한 맵과 gis 자료를 읽을 수 있는 것은 좋은데 사용자가 71pc로 포트를 두번 타서 그런지 확대 축소에 따른 표시 딜레이가 있으며, 오히려 맵 형 데이터는 cesium이나 leaflet과 같은 형태로 인터랙티브하게 볼 수 있게 하는 것은 어떤지 논의 후 구현해볼 필요가 있다." — 2026-10-12 요청

> "1 지도 방식은 oracle search를 통해 검색하고 해당 내용까지 반영하여 여전히(가)안이 유력한지 확인 후 (가)+oracle search 의견 반영해서 진행하자. 2번은 나중에 별도 작업, 3번은 둘다 지원. 특히 71pc 의 seoul_geomodel 프로젝트의 vtk 시스템을 참조해서 관련된 배경지도맵 api 정보들이 있으므로 해당 환경파일을 사용자가 승인하므로 74pc에 복사해 와서 사용하자. 4번은 md 그림문제와 관련하여 GAID에서 실수하지 않게 프로그램 지침으로 md파일에서 그림파일이 깨지지 않게 하기 위한 간단한 프로그램 지침을 포함해두어 에이전트에 상관없이 실수하지 않게 해두자." — 2026-10-12 결정

완료 기준: (1) 웹 조사로 지도 방식을 다시 확인하고 그 권고를 반영해 확대·축소 대기를 줄입니다. (2) 배경지도 없음과 온라인 배경지도를 모두 지원하고, 키 없이·오프라인에서도 지도가 동작해야 합니다. (3) 3차원(Cesium) 보기는 이번 범위가 아닙니다. (4) 어떤 에이전트가 써도 Markdown 그림이 깨지지 않게 하는 간단한 규칙을 둡니다.

## 2. 수행한 것

1. 웹 조사(ChatGPT 고급 조사)로 OpenLayers 타일 방식, MapLibre, Leaflet을 비교했습니다. 느린 원인은 지도 라이브러리가 아니라 화면을 움직일 때마다 분석 프로그램을 새로 띄워 한 장의 그림을 만드는 전달 방식이었습니다. OpenLayers는 한국 투영 좌표계(EPSG:5186/5179)를 그대로 보여 주고 다른 좌표계의 배경지도를 맞춰 그릴 수 있어 계속 쓰는 편이 낫다는 결론이었습니다.
2. 조사 권고대로 지도를 작은 타일로 나누어 보내도록 바꿨습니다. 분석 프로그램은 몇 개만 계속 켜 두고 자료 파일을 열어 둔 채 타일을 만듭니다. 한 번 만든 타일은 서버와 브라우저에 보관해 다시 쓰고, 개요(축소본)가 없는 큰 래스터는 표시용 축소본을 따로 만들어 둡니다. 원본 파일은 바꾸지 않습니다.
3. 투영 좌표계가 선언된 자료는 그 좌표계로 바로 보여 주고, Web Mercator로 바꿔 볼 수 있습니다. 지도를 클릭하면 원본 파일에서 그 위치의 실제 픽셀값을 읽습니다. 벡터는 레이어 전체를 한 번 받아 그리고, 너무 크면 화면 범위만 나누어 받습니다.
4. 배경지도를 고를 수 있게 했습니다(하위 작업). 기본은 없음이며, OpenStreetMap, 국토지리정보원 바로e맵(일반·영상·백지도), 한국지질자원연구원 1:5만 지질도 겹쳐 보기를 지원합니다. 승인받아 PC74로 복사한 키 파일을 서버만 읽고, 키는 브라우저·기록·저장소에 남기지 않습니다.
5. Markdown 그림 경로 규칙을 넣었습니다. 모든 에이전트 지침에 "그림 경로는 Markdown 파일이 있는 폴더 기준"이라는 한 줄을 넣고, 에이전트(하위 에이전트 포함)가 Markdown을 저장하면 열리지 않는 그림 링크와 고칠 경로를 바로 알려 줍니다.

## 4. 검증

- 과학적 검증: 타일 색과 위치를 정답이 정해진 합성 래스터(범주 값, 결측값, 좌표계 없는 자료, 지리 좌표 자료)로 대조했습니다. 클릭한 픽셀값은 원본 파일의 행·열 값과 일치했습니다. 표시용 축소본을 만든 뒤에도 원본 파일의 크기와 수정 시각은 바뀌지 않았습니다. 실제 자료의 지질 해석은 평가 대상이 아닙니다.
- 소프트웨어 검증: 서버·화면 단위 시험, 실제 GDAL을 쓰는 known-answer 시험, 저장소 전체 검사(`scripts/check`), 실제 브라우저 확인(래스터·벡터·EPSG:5186 보기, 배경지도 선택)을 했습니다. 시험 통과는 결과가 과학적으로 옳다는 뜻이 아닙니다.
- 지연 측정: PC71의 브라우저(자동화된 Chrome)가 SSH 터널로 PC74에 붙는, 사용자와 같은 경로에서 쟀습니다. 사람이 직접 화면을 보며 잰 체감 시간은 아닙니다. 서버만 따로 잰 타일 한 장은 처음 만들 때 중앙값 13–24 ms, 다시 요청할 때 2–3 ms였습니다.

## 5. 한계

- 래스터 타일과 색 범위는 표시용 표본입니다. 색 범위는 축소 표본의 2–98 백분위수로 정하므로 극단값은 같은 색으로 보입니다. 분석은 원본 파일로 해야 합니다.
- 벡터는 2만 개 피처·40만 꼭짓점까지 한 번에 받고, 그보다 크면 화면 범위의 500개씩만 보여 줍니다. 매우 큰 벡터용 벡터 타일 방식은 이번에 넣지 않았습니다.
- 국토지리정보원·지질자원연구원 지도를 서버를 거쳐 받는 방식이 각 기관 약관에서 허용되는지는 조사로 확인되지 않았습니다. 키는 사용자 본인 것만 쓰고, 그림을 디스크에 쌓아 두지 않으며, 출처 표기를 항상 보여 줍니다. 네이버 지도는 원시 타일 사용 허가가 확인되지 않아 넣지 않았습니다. OSM은 브라우저가 직접 받으며 일괄 내려받기는 하지 않습니다.
- 좌표계 정보가 EPSG 코드 없이 적힌 shapefile(예: 이름 없는 횡단 메르카토르)은 원본 좌표계 보기 대신 Web Mercator로 보여 줍니다.
- 3차원(Cesium) 보기는 범위 밖이며 별도 작업으로 남깁니다.
- 검토용 앱(사용자가 PC71에서 보는 인스턴스)은 이번 결과로 아직 갱신하지 않았습니다. 갱신은 hub가 사용자 요청에 따라 합니다.
