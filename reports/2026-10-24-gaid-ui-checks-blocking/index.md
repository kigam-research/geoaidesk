# impeccable·axe 점검을 막는 단계로 전환

## 0. 한눈에

| | |
|---|---|
| 요청 | 다른 PC 한 대에서 전체 점검을 돌려 PC74와 같은 결과가 나오면 impeccable과 axe를 막는 단계로 바꿉니다. |
| 결론 | PC70의 전체 점검이 네 도구 모두 PC74와 같은 결과를 냈고, impeccable과 axe를 막는 단계로 바꿨습니다. 화면 비교와 shadcn 검사기는 보고만 하는 단계로 남습니다. |
| 믿을 수 있는 정도 | 두 PC가 같은 판의 브라우저로 같은 견본 화면 네 조합을 점검해 결과 목록이 항목 단위까지 같았습니다. 막는 단계의 실패 안내는 일부러 결과를 만들어 한 번 확인했습니다. |

## 1. 요청한 것

> 권장 방법으로 하자. — 2026-10-24 요청

공용 부품 대비 보고서 6절의 선택지 가)에 대한 답입니다. 다른 PC 한 대에서 전체 점검을 한 번 돌려 같은 결과(impeccable 0건, axe 0건)가 나오면 두 도구를 막는 단계로 바꿉니다. 화면 비교와 shadcn 검사기는 보고만 하는 단계로 둡니다.

완료 기준: PC70의 결과를 PC74 결과 옆에 적습니다(도구별 건수, 코드 판, 브라우저와 글꼴). 둘 다 0건이면 두 도구를 막는 단계로 바꾸고, 실패할 때 부품 상태 견본 화면을 가리키는 안내를 넣고, 전환 규칙과 프로젝트 안내의 점검 설명을 고치고, PC74에서 전체 점검을 돌립니다.

## 2. 수행한 것

1. PC70에 고정 카탈로그 자산을 PC74에서 복사하고(해시 일치 확인), 지금 main 판의 작업용 사본을 만들어 전체 점검을 돌렸습니다.
2. 첫 실행은 백엔드 시험에서 멈췄습니다. 시험용 가짜 허브가 PC74 사용자 폴더 경로를 직접 적어 두어서 다른 사용자 이름의 PC에서는 폴더를 만들지 못했습니다. 경로를 각 PC의 홈 폴더 기준으로 고쳤습니다.
3. 둘째 실행은 통과했지만 브라우저 점검 셋이 건너뛰어졌습니다. PC70의 Node가 기관 인증서를 믿지 않아 점검용 브라우저를 내려받지 못했습니다. PC70 설정은 그대로 두고, 그 실행에만 시스템 인증서 묶음을 알려 주어 셋째 실행에서 네 도구가 모두 돌았습니다.
4. PC70 셋째 실행의 결과를 PC74 결과와 항목 단위로 비교했습니다.
5. impeccable과 axe를 막는 단계로 바꿨습니다. 막는 도구가 어떤 화면 조합을 점검하지 못하면 그것도 결과로 잡게 했습니다. 실패 안내에는 부품 상태 견본 화면을 여는 방법과 받아들인 부채로 올리는 곳을 적었습니다.
6. 전환 규칙의 전환 기록, UI 가이드, 프로젝트 안내, 전체 점검 단계 이름을 새 상태에 맞췄습니다. PC74에서 전체 점검을 돌리고, 일부러 결과를 하나 만들어 실패 안내를 확인했습니다.

## 3. 결과

그림 없음: 이번 작업은 화면을 바꾸지 않았고 점검 결과는 건수로 비교합니다.

### 3.1 두 PC의 점검 결과

| 점검 | PC74 | PC70 | 같은가 |
|---|---|---|---|
| impeccable (코드 검사 + 견본 화면 네 조합) | 0건 | 0건 | 같음 |
| axe 접근성 검사 (견본 화면 네 조합) | 0건 | 0건 | 같음 |
| 화면 비교 (네 조합, 기준 화면 대비) | 차이 0건 | 차이 0건 | 같음 |
| shadcn 검사기 (GAID 화면 코드) | 248건 (서로 다른 항목 166개) | 248건 (서로 다른 항목 166개) | 항목까지 같음 |

| 환경 | PC74 | PC70 |
|---|---|---|
| 운영체제 | Ubuntu 24.04 | Ubuntu 26.04.1 |
| Node | 24.21.0 | 22.22.1 |
| 점검용 브라우저 | Chrome for Testing 153.0.8010.12 (Playwright 1.63.0 고정판) | 같음 |
| 화면 글꼴 | 저장소에 든 Pretendard | 같음 |
| 시스템 기본 글꼴 | Noto Sans CJK, Noto Sans Mono CJK | Noto Sans, DejaVu Sans Mono |

시스템 기본 글꼴이 달라도 화면 차이는 0건이었습니다. 견본 화면의 글자를 저장소에 든 Pretendard로 그리기 때문으로 추정합니다. 고정폭 글자가 어느 글꼴로 그려지는지는 따로 확인하지 않았습니다.

### 3.2 막는 단계로 바꾼 것

| 점검 | 전 | 후 |
|---|---|---|
| impeccable | 보고만 함 | 막음 |
| axe | 보고만 함 | 막음 |
| 화면 비교 | 보고만 함 | 보고만 함 |
| shadcn 검사기 | 보고만 함 | 보고만 함 |

막는 단계에서는 받아들인 부채 목록에 없는 결과가 하나라도 있으면 전체 점검이 실패합니다. 실패하면 이렇게 안내합니다. 개발 서버를 켜고 부품 상태 견본 화면을 열어 각 부품을 모든 상태에서 봅니다. 결과를 고치거나, 그 결과를 이유와 함께 받아들인 부채로 올립니다.

막는 도구가 일부 화면 조합만 점검하고 나머지를 점검하지 못하면 빠진 조합도 결과로 잡습니다. 견본 화면이 어느 조합에서 그려지지 않으면 그 조합의 결과 파일이 비는데, 이때 점검이 그대로 통과하지 않게 했습니다. 브라우저가 없거나 네트워크가 막혀 도구 자체가 돌지 못하면 전환 규칙대로 그 실행에서는 건너뛰었다고 적고 실패시키지 않습니다.

## 4. 검증

- 과학적 검증: 해당 없음(점검 도구 설정).
- 같은 결과인지: 두 PC의 결과 목록을 항목 열쇠 단위로 비교해 네 도구 모두 같았습니다. PC74 쪽은 공용 부품 대비 작업의 마지막 실행 결과이고, 그 뒤 main에는 화면 코드를 바꾸는 변경이 들어오지 않았습니다. PC70은 같은 main 판에 시험 경로 한 줄 수정만 더한 상태로 돌렸습니다.
- 실패 안내: 견본 화면에 대체 글이 없는 그림 하나를 잠시 넣고 두 도구만 돌려, 점검이 실패하고 안내가 나오는 것을 확인한 뒤 되돌렸습니다. axe가 네 조합에서 같은 결과 4건을 찾았고 점검이 실패로 끝났으며, 견본 화면 안내가 출력되었습니다. 화면 조합이 빠졌을 때 결과로 잡는 처리는 일부러 일으켜 보지 않았습니다.
- 소프트웨어 검증: PC70 셋째 실행에서 전체 점검을 통과했습니다. 백엔드 시험 2322개 통과(8개는 원래 건너뜀), 프런트엔드 시험 1326개 통과입니다. PC74에서도 막는 단계 설정으로 전체 점검을 통과했습니다. 백엔드 시험 2322개 통과(8개 건너뜀), 프런트엔드 시험 1326개 통과, 문구·UI 검사 오류 0입니다. 같은 실행의 점검 묶음 결과(shadcn 248, impeccable 0, 화면 차이 0, axe 0)는 PC70과 항목까지 같습니다.

## 5. 한계

- 자동 점검은 여전히 견본 화면 하나만 봅니다. 실제 화면(허브, 서재, 작업 공간)의 대비 문제는 막는 단계로 바꾼 뒤에도 잡지 못합니다.
- 기관망 안의 PC에서 Node가 기관 인증서를 믿지 않으면 브라우저를 처음 내려받지 못하고, 브라우저 점검 셋이 건너뛰어집니다. 이때 전체 점검은 통과하고 건너뛰었다고만 적습니다. PC70은 이번 실행에만 인증서를 알려 주었고, PC70 사용자 설정은 바꾸지 않았습니다. 브라우저는 이제 PC70에 내려받아져 있어 다음 실행에서는 다시 내려받지 않습니다.
- 화면 비교는 이번에도 두 PC에서 차이 0건이었지만, 요청대로 보고만 하는 단계로 남겼습니다.
