# GAID 홍보 영상 lemo판: v4 메시지를 발표 영상 스타일로 다시 만든 100초 영상과 40초 영상 (내부 검토용, 음악·효과음)

## 0. 한눈에

| | |
|---|---|
| 요청 | lemo-opuscar에서 GAID 허브 홍보에 맞는 스타일을 골라 v4 메시지로 영상을 만듭니다. 작업 중에 40초 홍보판, 두 예제 사용, 모션그래픽 속 창 배치, 박스·전환·고리 장면 개선 요청이 더해졌습니다. |

| 믿을 수 있는 정도 | 실제 화면은 v2·v3 때 GAID에서 촬영한 것이고 화면 문구는 바꾸지 않았습니다. 배경, 연구 순환, Second brain 장면은 설명 그림입니다. 음량과 빈 화면은 완성 파일에서 측정했고, 소리는 측정값과 파형으로만 확인했습니다(5절). |
| 결정할 일 | 없음. 영상 검토 의견을 받습니다. |

## 1. 요청한 것

> V4와 병렬로 진행가능하면 brag 영상 작업시작하자. 그리고 또 별도로 https://github.com/lemomo-ai/lemo-opuscar 에서 GAID 허브 시스템 홍보에 적합한 것을 선정해 brag영상 제작작업과 동일한방식으로 lemo작업도 시작하자. — 2026-10-24 요청

> 메시지는 동등해도 되는데 연출은 오히려 더 자유롭게 홍보성으로 만들자. 그리고 분량은 40초로하고 코드로 된 영상 기반으로 전면 새로 만들어도 좋다. 현재 촬영자료가 있다고 너무 v4스타일로 만들필요는없다. 현재 렌더링중인것은 계속만들고 별도로하나더 생성하자. — 2026-10-24 작업 중 요청

> 예제도 yilgarn예제와 PGI예제를 둘다써도되고 꼭 모든 워크플로우가 하나의 예제만 보이는것이 아니라 적합한것을 사용하고 촬영 에셋이 영상 전 영역을 차지하지 않고, 해당 기능을 소개하는 모션그래픽속의 창요소처럼 보여도되므로 상품성 높은 홍보영상으로 제작하자. — 2026-10-24 작업 중 요청

> 102초판의 경우 피드백으로 사각형 박스로 영역을 표시할 때 올바르게 표시해야한다. 현재 해당 영역을 올바르지 못하게 표시하거나 화면에서 엉뚱한 곳을 가리키거나 화면을 자르는 사각 박스가 있는 경우도 있다. 102초판의 경우 장면 전환을 스무스하게 하고 영상을 최적화한다면 꽤 적절한 영상으로 활용가능하다고 생각한다. 자가 검토하여 무엇이 부족했는지 진단후 개선하자. — 2026-10-24 1차 영상 피드백

> lemo 버전에서 아쉬운 것은 GAID로고 이후  GAID 허브와 GAID 시스템을 설명하는 18초 이후 장면의 고리 애니메이션 품질이 낮다. V4 방식이나 BRAG 방식을 보고 개선할 필요가 있다. — 2026-10-24 1차 영상 피드백

"동일한 방식"은 brag판에 정한 조건입니다. 메시지는 v4와 같고, 90~105초, 음악과 효과음만 쓰고 내레이션은 없으며, 내부 검토용이고, v4를 대체하지 않고 나란히 둡니다.

완료 기준은 다음과 같습니다.
- 스타일 후보 2~3개를 보여 드리고 하나를 고릅니다.
- v4 이야기를 그 스타일로 다시 만듭니다. 1920×1080, 30fps, 스테레오 음악과 효과음, 90~105초입니다.
- 40초 홍보판을 따로 만듭니다.
- 1차 피드백을 반영합니다. 박스는 맞는 영역만 가리키고, 장면 전환은 부드럽게 하며, 고리 장면은 v4·brag 수준으로 고칩니다.
- GAID 규칙을 지킵니다. 화면 이름은 "AI agent"와 "GAID"로 쓰고, 만든 숫자와 독점 자산·글꼴을 쓰지 않으며, "개념도" 같은 모서리 표시를 넣지 않습니다.

## 2. 수행한 것

1. lemo-opuscar(커밋 3961ddb)를 받아 59개 스타일을 검토했습니다. 후보 세 개를 작업 탭과 검토용 사본에 포스터와 함께 보여 드렸습니다.
   - Dark Tech Keynote(선택): 소프트웨어 발표 영상의 문법입니다. "흩어진 것이 한 번의 동작으로 격자에 모인다"는 이 스타일의 기본 장면이 v4 배경 이야기와 같습니다. 강조색 하나를 GAID 파랑으로 쓰고, 소리도 흩어진 음에서 한 조성의 음으로 모입니다.
   - Swiss Motion Graphics: GAID의 도폭 스타일과 가깝지만, v4가 이미 밝고 평평한 화면이라 차이가 작습니다.
   - Living Screencast: 화면 녹화 문법이지만 픽셀 마스코트와 UI를 새로 그리는 것이 핵심이어서 실제 촬영본과 맞지 않습니다.
2. 연출안을 먼저 썼습니다. 구조 후보 세 개 중 "흩어짐 → 멈춤과 클릭 → 격자로 모임 → 순환"을 골랐고, 장면 목록, 박자 지도(120 bpm), 소리 설계표를 함께 정했습니다.
3. 장면을 코드로 그렸습니다. 배경은 GAID 어두운 화면 색이고, 글꼴은 Pretendard 하나입니다. 시연 구간은 실제 화면을 오른쪽 창에 한 배율로 두고, 왼쪽에 목적 문장과 기능 목록을 쌓았습니다. 지금 설명하는 기능은 선으로 화면의 파란 상자와 이어집니다. 포천 자철석 예제(v3 촬영본)에 Yilgarn 니켈 탐사 예제(v2 촬영본)의 지도, 연구노트, 연결 지도 장면을 더했습니다.
4. 음악과 효과음을 영상의 동작 목록에서 만들었습니다. 음악은 D 리디안 조성의 새 곡이고, 악기는 마림바, 비브라폰, 글로켄슈필 같은 공개(CC0) 샘플입니다. 효과음은 코드로 합성했습니다.
5. 1차 영상(102.3초)을 만든 뒤 피드백을 받아 자가 검토했습니다(7절). 박스마다 시작과 끝 프레임을 완성 파일에서 뽑아 화면 내용과 대조했고, 박스 좌표는 페이지에서 직접 재어 확인했습니다.
6. 2차 수정본을 만들었습니다.
   - 박스: 촬영 기록의 각 영역을 그 영역이 유효한 시간 구간 안에서만 씁니다. 다음 영역으로는 박스가 미끄러지듯 옮겨 가고, 창 가장자리에 닿는 영역은 안쪽으로 들였습니다.
   - 전환: 장이 바뀌어도 창을 접지 않습니다. 빛 띠가 지나가며 내용이 바뀌고, 왼쪽 글은 위로 빠졌다가 새 글이 올라옵니다. 시연이 끝나면 창이 오른쪽 위 작은 고리로 줄어들고, 그 고리가 Second brain의 첫 고리로 날아옵니다.
   - 고리 장면: v4·brag 구성을 어두운 화면으로 옮겼습니다. 로고 궤도가 커져 기울어진 큰 타원이 되고, 점이 돌며 단계 칩을 켭니다. 중심에는 G가 남고, 안쪽 호 두 개가 GAID 허브와 GAID 시스템을 나눕니다.
   - 길이와 읽기: 박스가 없거나 화면 배치가 바뀌는 구간을 잘랐습니다. 장 마지막 컷 네 곳은 끝 화면을 0.5~1.3초 멈춰 두었습니다. Second brain 문장은 4초 넘게 보입니다.
7. 40초판은 하위 작업에 맡겼고, 작업 중 받은 요청을 그대로 전달했습니다.

## 4. 검증

- 과학적 검증: 해당 없음. 시연에 나오는 분석은 v2·v3 때 예제 자료로 한 홍보용 실행입니다.
- 영상: 완성 파일을 다시 읽었습니다. 100.4초, 3,012프레임, 1920×1080, 30fps, H.264입니다. 검은 화면 검사에서 걸린 구간은 없습니다. 렌더 중 브라우저 오류는 없었습니다(있으면 렌더가 실패합니다).
- 사각 박스: 박스 31개마다 시작 직후와 끝 직전 프레임을 완성 파일에서 뽑아 화면 내용과 대조했습니다. 모두 설명하는 영역을 감싸고, 창 밖으로 나가거나 창 가장자리에 겹치는 박스는 없습니다.
- 소리: 완성 파일의 음량은 −14.3 LUFS, 최대치 −1.9 dB, 음량 범위 6.1 LU입니다. AAC 인코딩 뒤의 최대치가 일정하지 않게 튀어서, 마스터링은 인코딩한 파일을 재서 최대치가 −1 dB 이하가 될 때까지 목표를 낮춥니다. 멈춤 구간의 신호가 0인 것을 확인했습니다.
- 장면: 미리보기에서 고리 장면, 장 전환, 시연→Second brain 연결, 마무리를 0.2~0.8초 간격 프레임으로 확인했습니다.
- 읽는 시간: 화면 글 44개 중 17개가 lemo의 읽기 시간 기준(한글 4.5자/초 + 1.5초)보다 짧습니다. 기능 목록 항목은 모두 2.3초 이상 보입니다. Second brain 문장은 4.0초와 4.3초입니다. 기준보다 짧은 나머지는 앞부분 제목 줄과 순환 장면의 설명입니다(5절).
- 검토용 앱: 쓰지 않았습니다. 새로 촬영하지 않았습니다.
