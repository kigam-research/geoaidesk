# GAID 채팅 답변과 연구노트의 문장 다듬기

## 0. 한눈에

| | |
|---|---|
| 요청 | 연구노트와 채팅 답변을 backbone 출력 방식(Attention Control Korean, humanizer)처럼 명료하게 쓰게 하기 |
| 결론 | 채팅 답변 규칙을 GAID 기본 지시에 넣었고, 연구노트용 문장 다듬기 스킬을 만들어 모든 지질 프로젝트에 넣었습니다. 기관 Qwen 시험에서 AI agent는 노트를 쓰기 전에 이 스킬을 읽었고, 답변은 결과로 시작했으며 본문의 장식용 굵은 글씨가 사라졌습니다. 노트는 바꾸기 전과 같이 해라체로 나왔습니다. |
| 믿을 수 있는 정도 | 기관 Qwen 한 모델, 같은 요청 하나로 바꾸기 전 1회, 바꾼 뒤 2회 돌린 비교입니다. 실행마다 분석 내용도 달라지므로, 차이가 모두 이번 변경 때문이라고 확정할 수 없습니다. 검토용 앱에는 아직 반영하지 않았습니다. |
| 결정할 일 | 1건 (6절) |

## 1. 요청한 것

> gaid-notebook-review와 관련하여 연구노트를 작성하거나 agent가 대화창에서 답변할 때 현재 backbone 워크트리 시스템의 출력 방식처럼 attention control korean과 휴머나이저 스킬을 사용하여 명료하면서 이해가 잘되도록 연구노트가 작성되고 답변 될 수 있게 하자. GAID시스템의 출력에 대한 피드백이다. — 2026-10-18 요청

> 따로 작은 작업으로 권장 방식으로 지적 처리하고 output 작업도 별도작업으로 진행하자. — 2026-10-18, hub의 범위 제안에 대한 답(이 작업이 "output 작업")

완료 기준: 채팅 답변은 Attention Control Korean의 원칙을 줄인 규칙을 따르고, 영어 대화에도 같은 원칙을 적용합니다. 연구노트는 humanizer 규칙(한국어 규칙 포함)을 GAID 스킬로 만들어 노트를 쓸 때 쓰게 합니다. 시작 프롬프트가 얼마나 늘었는지 재고, 가져온 글의 출처와 라이선스를 밝히고, 기관 Qwen으로 바꾸기 전과 후를 비교합니다. 화면 고정 문구는 범위 밖입니다.

## 2. 수행한 것

1. backbone의 두 원본을 읽었습니다. Attention Control Korean은 대화 답변 규칙이고, humanizer는 문서 문장 규칙입니다(영어 원본 약 32 KB, 한국어 규칙 약 12 KB). 두 원본과 그 상위 공개 저장소의 라이선스(모두 MIT)를 확인했습니다.
2. 채팅 답변 규칙을 영어 한 문단(728자)으로 줄여 GAID 기본 지시에 넣었습니다. 결과 먼저, 한 문장에 한 가지, 확인하지 않은 것은 확인하지 않았다고 쓰기, 수정·실행·시험·검증 구분, 인사·예고·맺음말 금지, 한국어 문장 규칙(합니다체, 명사형 서술·번역투·빈 헤지 금지)을 담았습니다. 다른 언어에도 같은 원칙을 적용합니다.
3. 연구노트용 스킬 `gaid-note-style`을 새로 썼습니다. humanizer의 26개 패턴 가운데 연구노트에 나오는 12개와 한국어 문장 규칙, 노트 형식을 지키는 규칙, 고친 뒤 수치·링크를 원문과 대조하는 순서를 약 5천 자로 담았습니다. 원문을 그대로 옮기지 않고 줄여 다시 썼습니다.
4. 이 스킬을 지질 프로젝트마다 넣었습니다. 프로젝트를 만들거나 채팅을 열 때 들어가고, 연구자가 고치지 않은 사본만 새 판으로 바뀝니다. 연구자가 지우거나 끈 사본은 다시 넣지 않습니다. 작업별로 스킬을 골라 보여 주는 채팅에서도 이 스킬은 항상 보입니다. 노트 지시에는 "노트를 쓰기 전에 이 스킬을 읽고 사실·수치·링크·확신 정도는 그대로 둔 채 문장을 다듬으라"는 한 문장을 더했습니다.
5. 시험용 앱 두 개를 따로 띄워, 지난 작업과 같은 요청(서울 1:25만 지질도의 암상별 면적표와 색 지도)을 기관 Qwen에게 맡겼습니다. 바꾸기 전 1회, 바꾼 뒤 2회입니다. 1차 결과를 보고 스킬의 문체·용어 규칙과 답변 규칙(대시 금지)을 고친 뒤 새 프로젝트에서 2차를 돌렸습니다.

## 3. 결과

그림 없음: 결과가 글이므로 원문 발췌와 표로 비교합니다.

### 3.1 채팅 답변

| 항목 | 바꾸기 전 | 바꾼 뒤 1차 | 바꾼 뒤 2차 |
|---|---|---|---|
| 첫 문장 | "완료했습니다. 좌표계는 … 그대로 썼고(재투영 없음) …" | "좌표계는 … 선언된 값 그대로 썼습니다." | "면적표와 지도를 완성했습니다. … 합계 면적은 2,012.92 km²이고, … 호상편마암이 … 절반을 차지합니다." |
| 표 밖 굵은 글씨 | 10곳(5쌍) | 0 | 0 |
| 문장을 잇는 대시(—) | 2 | 1 | 1 |
| 확인하지 않은 것 | "검증하지 않았습니다", "육안 검수하지 못했습니다" 2곳 | "원코드표는 확인하지 않았습니다", "눈으로 대조한 검증은 하지 않았습니다" | "중첩 여부는 별도로 검증하지 않았습니다" |
| 결정할 일 | 끝에 ①②③ 한 줄 | 노트의 결정할 일을 가리킴 | 끝에 결정 2건과 권장 이유 |

바꾸기 전 답변은 "**EPSG 코드는 없고 파라미터만** 선언돼 있습니다 — Transverse Mercator, …"처럼 강조와 대시로 문장을 이었습니다. 바꾼 뒤 2차 답변은 결론을 첫 문장에 쓰고, 좌표계 확인 사실을 목록으로 나눴습니다. 다만 2차 답변에도 산출물 줄 하나에 대시가 남았고, 분석 중간에 "작업은 이미 완료되었습니다. 연구노트를 작성하고 결과를 정리해 드립니다." 같은 예고 문장을 썼으며, 한자 한 글자("計算値")가 섞였습니다.

### 3.2 연구노트

| 항목 | 바꾸기 전 | 바꾼 뒤 1차 | 바꾼 뒤 2차 |
|---|---|---|---|
| 노트 쓰기 전 스킬 읽기 | 해당 없음 | 읽음 | 읽음 |
| 표 밖 굵은 글씨 | 6곳(권장 표시를 굵게) | 0 | 0 |
| 문장을 잇는 대시(—) | 1 | 0 | 0 |
| 빈 헤지("~로 보인다") | 1 | 0 | 0 |
| 문체 | 해라체 | 해라체 | 해라체 |
| 영어 낱말 | 중간("extent", "datum") | 많음("polygon", "dissolve", "metre", "hue") | 줄어듦("폴리곤", "중앙경선"; "False Easting"은 남음) |
| 결정할 일의 권장 이유 | 굵은 괄호 한 구절 | 문장 1~2개 | 문장 1~2개 |

바꾸기 전 노트의 한 일 1번은 "투경: 중앙경도 127°E, … 가동칭 200,000 / 가북칭 600,000"처럼 낯선 줄임말을 썼습니다. 바꾼 뒤 2차 노트는 같은 내용을 "원점 위도 38°, 중앙경선 127°, 축척 1.0, False Easting 200,000 m …"로 풀어 쓰고, EPSG 코드를 대조한 근거와, 처음 고른 좌표계를 버린 이유(총면적이 0.3% 커짐)를 문장으로 적었습니다.

스킬에 "한국어 노트는 합니다체"라고 적어 2차를 돌렸지만, AI agent는 해라체로 썼습니다. 원본 한국어 규칙은 원문 문체를 유지하라고 하므로, 지금 스킬은 "한 노트 안에서 문체를 섞지 않는다"로 되돌렸습니다. 문체를 하나로 정할지는 6절의 결정입니다.

2차 노트에는 오타("셤프파일")와 어색한 연결("계산했고, 그리고")이 있고, 1차 노트에는 띄어쓰기가 빠진 곳이 하나 있습니다.

## 4. 검증

- 과학적 검증: 해당 없음. 노트 속 면적 값은 AI agent가 계산한 시험 내용이며 이 작업에서 검증하지 않았습니다.
- 비교의 근거 점검:
  1. 기준과 단위: 같은 요청, 같은 모델, 같은 표본 자료, 새 프로젝트에서 실행했습니다. 표의 수는 글자 패턴을 센 값입니다.
  2. 반복 횟수: 바꾸기 전 1회, 바꾼 뒤 2회입니다. 반복 간 편차는 재지 않았습니다.
  3. 다른 설명: 실행마다 AI agent가 고른 분석 경로가 다릅니다. 바꾸기 전 실행은 암상 사이 겹침을 계산했고 바꾼 뒤 2차는 계산하지 않았습니다. 이런 내용 차이는 이번 변경과 무관할 수 있습니다.
  4. 필요한 크기: 결론은 "결과부터 쓰기와 장식 제거가 실제 출력에 나타났다"는 수준이며, 비율이나 통계적 차이를 주장하지 않습니다.
  5. 확인하지 않은 것: 다른 모델, 영어 대화, 긴 연구 과제, 결정에 답한 뒤 노트를 고치는 단계에서는 시험하지 않았습니다. 마지막에 되돌린 문체 규칙 한 줄도 다시 실행해 보지 않았습니다.
- 소프트웨어 검증: 새 시험 8개(규칙 길이 상한, 스킬 이름과 출처 표시, 항상 보이는 스킬, 한 번 넣기·고치지 않은 사본만 갱신·지운 사본 유지)와 서버의 지질 시험 42개 파일 334개가 통과했고, 서버 타입 검사를 통과했습니다. 프로젝트를 만들 때 스킬이 하나 더 들어가므로 기존 시험 둘을 고쳤습니다. 프로젝트 생성 시험의 기대값을 2개에서 3개로 바꿨고, 배포 스모크 시험은 이 스킬을 카탈로그 밖 스킬로 세지 않고 들어갔는지 따로 확인합니다. 마무리 단계의 첫 전체 검사는 이 스모크 시험 때문에 실패했고, 고친 뒤 스모크 시험이 통과했습니다.

## 5. 한계

- 규칙은 지시일 뿐이라 모델이 따르지 않을 수 있습니다. 시험에서도 합니다체 지시, 대시 금지 일부, 중간 예고 금지는 지켜지지 않았습니다.
- 지금 있는 프로젝트에는 채팅을 처음 열 때 스킬이 들어갑니다. 이미 열려 있는 채팅은 이전 지시와 스킬 목록을 그대로 씁니다.
- 노트 스킬은 노트를 쓸 때마다 읽으므로, 한 분석에 약 5천 자를 더 읽습니다.
- 원본 규칙의 한국어 판은 KIGAM 비공개 저장소(backbone)에 있습니다. GAID에는 그 내용을 줄여 다시 쓴 글만 넣었고, 상위 공개 원본(MIT) 두 곳의 저작권 표시를 붙였습니다.
- 검토용 앱에는 아직 반영하지 않았습니다. 반영은 병합 뒤 hub가 맡습니다.

## 6. 결정할 일

1. 연구노트 문체를 하나로 정할까요?
   - 가) 정하지 않음. AI agent가 노트마다 한 문체로 씁니다(시험에서는 해라체).
   - 나) 합니다체로 고정 (권장: 요청한 backbone 출력 방식의 보고서와 채팅 답변이 모두 합니다체입니다. 스킬 지시만으로는 따르지 않았으므로 노트 지시에 넣고 다시 시험해야 합니다.)

## 7. 대체되었거나 실패한 시도

<details><summary>펼치기 — 2건</summary>

- 스킬에서 합니다체를 "바꾸지 않을 것" 목록에 넣은 1차 판: AI agent가 자기 초안의 해라체를 그대로 두었습니다. 2차 판에서 "해라체 초안은 합니다체로 고친다"로 옮겼지만 역시 해라체로 썼습니다. 지금 판은 "한 노트 안에서 문체를 섞지 않는다"입니다.
- humanizer 원문(약 32 KB)과 한국어 규칙(약 12 KB)을 그대로 넣는 방안: 노트를 쓸 때마다 읽기에 64K 문맥 모델에는 너무 커서 쓰지 않았습니다.
