# GeoAIDesk 실행 기반 — 고정 카탈로그, 준비된 환경, 파일 요약, 로컬 모델 설정 (WP03 gaid-runtime)

## 0. 한눈에

| | |
|---|---|
| 요청 | 계획서 WP03: 준비된 분석 환경, 정확한 카탈로그 설치, 쓸모 있는 파일 요약, 실제로 쓸 수 있는 로컬 모델 설정 |

## 1. 요청한 것

> "2번 GeoAIDesk(약칭 GAID), 나머지는 권장방식으로 하자." — 2026-10-11 계획 결정
>
> "구현 시작하자." — 2026-10-11 구현 시작 요청

skill_hub hub가 이 요청에 따라 계획서의 WP03 `gaid-runtime`을 geoaidesk로 보냈습니다. 완료 기준(계획서 원문 번역):
helper·분석 두 환경에 필요한 패키지가 있다, 선택한 모델·컨텍스트가 유지된다, 시작 프롬프트 예산이 보인다,
작업별 스킬 노출이 원본 스킬 패키지를 손상하지 않는다, 부적합한 대용량 파일 읽기는 범위가 정해진 다음 행동을
돌려준다. 결정적 테스트가 이 동작과 기존 프로젝트 보존을 확인한다. WP04·WP05·WP07이 쓸 안정된 연결 지점을 공개한다.

## 2. 수행한 것

1. skill_hub의 최신 카탈로그 0.2.0(스킬 13개, 작업 흐름 7개)을 기준 커밋에서 두 번 내보내 같은 파일이 나오는 것을 확인하고, 앱이 그 한 파일만 받아들이도록 버전과 해시를 고정했습니다. 앱은 파일 전체·각 파일·각 스킬 패키지의 해시를 모두 확인한 뒤에만 설치하고, 다른 카탈로그로 대신 채우지 않습니다.
2. 설치는 기존 설치기(스킬 동기화)를 그대로 거치게 해, 사용자가 고친 스킬·직접 설치한 스킬·지운 스킬을 건드리지 않고 카탈로그 스킬만 더합니다.
3. 채팅마다 "모델에게 보여 줄 스킬"을 한 번 기록하고 적용합니다(전체 / 카탈로그 / 작업 흐름별). 스킬 파일은 옮기거나 고치지 않고, 숨긴 스킬도 직접 호출로는 쓸 수 있습니다. 채팅 입력창의 컨텍스트 게이지 옆에 시작 프롬프트 크기와 새 채팅의 스킬 범위 선택을 두었습니다.
4. 카탈로그가 선언한 기본·GIS 패키지(numpy, pandas, lasio, pyproj, rasterio, geopandas 등 13개 모듈)를 미리보기용 helper 환경과 새 프로젝트의 분석 환경에 넣었습니다. 기존 프로젝트의 환경 파일은 바꾸지 않고, 필요하면 사용자가 "준비" 버튼으로 선언된 패키지만 추가합니다.
5. 지질 파일 하나를 브라우저와 에이전트가 같은 방식으로 요약하는 검사기를 만들었습니다(검층·shapefile·GeoTIFF·GeoJSON·표). 에이전트가 큰 자료 파일을 통째로 읽으려 하면 그 요약과 다음에 쓸 도구·Python 예시를 대신 돌려줍니다.
6. 로컬 모델(Ollama)의 실제 컨텍스트 설정을 확인하고, 명시적 컨텍스트로 앱 모델 목록에 등록하고 기본값으로 저장하는 설정 카드를 만들었습니다. 1–5 중 환경·로컬 모델·파일 검사는 하위 작업 세 개가 병렬로 맡았고 이 작업에 합쳤습니다.

추가로 확인된 것:

- 파일 요약 표본(2026-10-10 체험 파일): shapefile은 면 133개·속성 22개·선언된 좌표계 WKT를 보였고 EPSG를 지어내지 않았습니다. GeoTIFF는 EPSG:5186, 실수형 밴드 하나로 읽혀 더 이상 "현미경 영상"으로 분류되지 않습니다. 좌표 정보가 없는 일반 TIFF는 기존 영상 뷰어로 열립니다.
- 앱의 Pi 런타임은 컴퓨터 사용자의 공용 에이전트 스킬 폴더도 읽습니다. "모든 스킬" 범위에서는 이 스킬들이 모델에게 보이고, 카탈로그·작업 흐름 범위에서는 숨겨집니다.
- 계획서가 남긴 확인 사항: 가져온 스킬 두 개(geopandas, uncertainty-and-units)는 설명서가 스크립트 위치를 skill_hub 저장소 기준 경로로 적습니다. 이 경로는 앱의 설치 구조에서 그대로는 열리지 않습니다. 실제 스크립트는 각 스킬 폴더 안의 스크립트 폴더에 있습니다.

## 4. 검증

- 과학적 검증: 해당 없음 — 분석 결과를 만드는 작업이 아닙니다. 파일 요약 값은 표본 파일에서 직접 읽은 메타데이터이고, 해석은 포함하지 않습니다.
- 소프트웨어 검증:
  - 카탈로그: 두 번 내보낸 아카이브의 해시가 같았습니다. 다음 경우가 시험으로 확인됩니다: 해시가 다른 아카이브 거부, 패키지 하나가 바뀐 아카이브 거부, 파일이 바뀐 아카이브 거부, 링크 항목이 든 아카이브 거부, 손으로 고친 캐시 복원, 아카이브가 없을 때 찾아본 위치 보고. 실제 0.2.0 아카이브에서 스킬 13개와 작업 흐름 7개를 확인했습니다.
  - 기존 프로젝트 보존과 버전 갱신: 업스트림 시절 프로젝트에 적용해도 기존 스킬의 해시가 바뀌지 않았습니다. 새 버전으로 바뀔 때 손대지 않은 스킬만 따라가고, 사용자가 고친 스킬은 그대로, 지운 스킬은 다시 설치하지 않았습니다.
  - 스킬 노출: 실제 Pi 세션을 만들어 시스템 프롬프트에 노출된 스킬만 들어가는 것을 확인했습니다. 프로젝트 기본값을 바꾼 뒤 다시 열어도 기록된 범위가 유지되고, 기록 이전의 채팅은 그대로였습니다. 미리보기는 기록이나 세션 파일을 남기지 않았습니다.
  - 환경: 선언된 13개 모듈을 helper 환경과 새 프로젝트 환경에서 실제로 import했습니다(26/26). helper 환경 잠금 파일은 배포 대상 네 플랫폼에서 해석됩니다.
  - 파일 검사와 읽기 안내: 합성 표본으로 검층·shapefile(.prj 유무)·GeoTIFF(좌표 정보 유무)·GeoJSON·CSV를 시험했습니다. 가짜 모델 응답을 쓰는 실제 세션에서, 막힌 읽기의 안내문이 모델이 받는 도구 결과로 전달되는 것을 확인했습니다.
  - 로컬 모델: 가짜 Ollama 서버로 상태 읽기·컨텍스트 불일치 표시·파생 모델 생성·설정 저장과 재시작 후 읽기를 시험했습니다. 실제 Ollama는 바꾸지 않았습니다.
  - 운영 모드 smoke: 빈 데이터 홈에서 설치·시작·정지·재시작을 했고, 카탈로그 스킬 13개만 설치되고 제외 대상 4개는 없었습니다. 새 채팅 시작 프롬프트 추정값은 25,049 토큰이었고, 재시작 후에도 프로젝트가 유지되었습니다.
  - 선언된 전체 검사 결과는 마무리 단계의 검사 기록에 남습니다(부록 A).
  - 테스트 통과는 결과가 쓸모 있다는 증거가 아닙니다. 로컬 모델로 검층 QC나 지도 작업을 다시 수행해 보는 시험은 하지 않았습니다.

## 5. 한계

- 시작 프롬프트에서 가장 큰 부분은 도구 설명입니다(약 19.1K 토큰: 하위 작업 위임, 연구 노트, 결과 카드 순으로 큼). 따라서 이 작업의 스킬 노출 조정만으로는 32K 로컬 모델에서 쓸 만한 여유가 생기지 않습니다(6절 결정 1).
- 표시되는 예산은 시스템 프롬프트와 도구 설명의 글자 수로 낸 추정입니다. 대화 내용과 모델별 채팅 형식의 추가분은 빠집니다. 2026-10-10 체험에서 비슷한 상태의 실제 첫 요청은 66,423 토큰이었으므로, 실제 사용량은 첫 응답 뒤 기존 게이지로 확인해야 합니다.
- 카탈로그 아카이브(6.9 MB)는 Git 한도를 넘어 이 PC(PC74)와 PC71의 자산 폴더에만 있습니다. 공개 저장소를 새로 받은 사용자는 아카이브를 받을 곳이 없어 카탈로그 스킬이 설치되지 않습니다. 이때 앱은 찾아본 위치를 보고하고, 다른 카탈로그로 대신 채우지 않습니다(6절 결정 2). GitHub CI에서도 같은 이유로 "아카이브 없음" 경로만 확인됩니다.
- 이 아카이브는 skill_hub의 기준 커밋에서 이 작업이 직접 내보냈습니다. skill_hub 쪽에서 같은 해시를 자기 결과로 등록하는지는 확인하지 않았습니다.
- 기존 프로젝트에서 K-Dense 쪽과 이름이 같은 가져온 스킬 5개는 이전 사본이 유지됩니다. 카탈로그 판으로 바꾸려면 설정에서 갱신해야 합니다.
- 로컬 모델 항목은 비용 0의 "사용량 과금" 종류로 분류됩니다. 프로젝트 지출 한도를 이미 넘긴 상태라면 비용이 0이어도 실행이 거부됩니다.
- 32K·64K 로컬 프로필은 "제안, 미시험"으로만 표시됩니다. 98K 기준값은 한 PC에서 한 번 기록한 체험값이며, CPU로 18% 넘어간 상태였습니다.

## 6. 결정할 일

1. 로컬 모델의 최소 컨텍스트를 어떻게 안내할까요? 도구 설명만 약 19K 토큰이라 32K 창에서 출력 8K를 예약하면 카탈로그 범위는 이미 넘치고, 작업 흐름 하나로 줄여도 대화 자리가 약 1K 남습니다.
   - 가) 64K 이상을 로컬 모델 최소로 안내하고(32K 제안 프로필 제거), 64K·98K 구성을 WP10에서 실제 과제로 시험합니다. (권장: 도구를 최대한 빼도 32K에서는 대화 자리가 수천 토큰에 그치고, 핵심 도구를 빼면 연구 기록 기능이 사라지기 때문입니다.)
   - 나) 32K 지원을 목표로, 로컬 모델용으로 도구 노출을 줄이는 작업 패키지를 새로 만듭니다(예: 원격 계산·PDF 주석·이미지 생성 도구 숨김).
2. 공개 설치에서 카탈로그 아카이브를 어디서 받게 할까요?
   - 가) geoaidesk 공개 저장소의 GitHub Release에 카탈로그 아카이브를 올리고, 앱이 고정된 해시로 내려받게 합니다. WP10 릴리스 작업에서 진행합니다. (권장: 앱 배포와 같은 공개 경로이고, 해시 고정으로 다른 판이 섞이지 않기 때문입니다.)
   - 나) 앱 릴리스 묶음(소스 아카이브)에만 카탈로그를 동봉하고, 저장소를 직접 받은 사용자는 수동으로 넣게 합니다.

## 7. 대체되었거나 실패한 시도

<details><summary>펼치기 — 4건</summary>

- helper 환경을 Python 3.11까지 포함해 잠그려 했으나, 카탈로그의 numpy 하한(2.5.3)이 Python 3.12 이상을 요구해 실패했습니다. 대신 잠금 대상을 배포 네 플랫폼의 Python 3.12 이상으로 한정했습니다. 기존 요구 버전 표기는 바꾸지 않았습니다.
- 첫 smoke에서는 카탈로그 확인 요청이 서버를 정지한 뒤에 실행돼 연결이 거부되었습니다. 검사 순서를 고쳐 다시 실행했고 통과했습니다.
- 처음 만든 노출 규칙은 앱이 함께 설치하는 위임 안내 스킬 두 개까지 숨겼습니다. 앱 기능 안내이므로 모든 범위에서 보이도록 바꿨습니다.
- 하위 작업의 별도 job 실행은 저장소에 있는 환경변수 예시 파일 때문에 스냅샷 검사에서 시작되지 않았습니다. 검사는 task 마무리 경로로 대신 실행했습니다.

</details>
