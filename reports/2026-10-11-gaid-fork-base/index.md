# GeoAIDesk 배포 기반 (WP02 gaid-fork-base)

## 0. 한눈에

| | |
|---|---|
| 요청 | GeoAIDesk(GAID)를 별도 공개 fork로 정하고 구현을 시작한다. 첫 앱 패키지는 독립 설치·출처 표기·릴리스 준비가 된 fork 기반이다. |
| 결론 | 완료 기준 다섯 가지를 모두 충족했습니다. 새로 받은 소스에서 GeoAIDesk 실행기가 의존성 설치, 화면 빌드, 서비스 시작을 하고, 중지·재시작 뒤에도 프로젝트와 파일이 남습니다. 문서 스킬 4종은 받지 않으며 사용자 자료는 소스 폴더 밖에 저장됩니다. |
| 믿을 수 있는 정도 | Linux(이 PC)에서 실제 실행으로 확인했습니다. Windows 기본 환경과 macOS에서는 실행하지 않았고, 모델 연결과 분석 작업은 이 패키지 범위가 아니어서 시험하지 않았습니다. |
| 결정할 일 | 없음. 확인 1건(공개 이슈 기능 켜기)을 task 문서에 남겼습니다. |

## 1. 요청한 것

> 2번 GeoAIDesk(약칭 GAID), 나머지는 권장방식으로 하자. — 2026-10-11 요청

> 구현 시작하자. — 2026-10-11 요청

완료 기준(계획서 WP02): 새로 설치하면 연구 작업 화면이 열린다. 운영 모드의 시작·중지·재시작이 프로젝트를 보존한다. 제외한 문서 스킬을 자동으로 받지 않는다. 업스트림 검사를 유지한다. 사용자 자료 위치가 소스 checkout과 분리된다.

## 2. 수행한 것

1. 배포 정보 파일을 만들었습니다: 제품 이름·버전(0.1.0, 미리보기)·릴리스 표기, 사용자 자료 위치, 기본 설정, 제외 출처를 한 곳에 적은 배포 설명서와, 기반 업스트림 판(K-Dense BYOK 0.15.0)과 고정한 핵심 패키지 판을 적은 잠금 파일입니다.
2. 업스트림 실행기에 운영 모드를 좁게 추가했습니다. 고정된 의존성 목록 그대로 설치하고(목록이 바뀐 때만), 화면 소스가 바뀐 때만 다시 빌드하며, 개발 서버 대신 운영 서버로 화면을 띄웁니다. 기존 개발용 실행기의 동작은 그대로입니다.
3. GeoAIDesk 실행기(Linux/macOS용, Windows용)를 만들었습니다. 사용자 자료(프로젝트, 모델 로그인, API 키, 내려받기 캐시)를 사용자 홈의 전용 폴더에 두고, 자료 위치가 소스 폴더 안이면 시작을 거부합니다.
4. 업스트림이 자동으로 받던 문서 스킬 4종(Word·PDF·PowerPoint·Excel용)을 받지 않게 하고, 스킬 목록 자동 갱신을 껐습니다. 업데이트 알림은 업스트림이 아닌 GeoAIDesk 릴리스를 보게 했습니다.
5. 출처 표기(업스트림 MIT 라이선스 원문 유지, 수정 고지, 제3자 고지)와 업스트림 동기화 절차, 업스트림 파일을 고친 위치와 담당 패키지 표를 만들었습니다.
6. 릴리스 절차를 바꿨습니다. 업스트림 방식(main에 반영될 때마다 업스트림 판 번호로 자동 공개)은 fork에서 잘못된 릴리스를 만들므로, GeoAIDesk 판 표기를 붙일 때만 초안 릴리스를 만들고 실제 커밋을 적은 릴리스 설명서를 함께 붙이게 했습니다. 업스트림 검사는 그대로 두고 GeoAIDesk 검사와 운영 모드 실행 시험을 덧붙였습니다.

## 4. 검증

- 과학적 검증: 해당 없음. 이 패키지는 설치·실행 기반이며 분석 결과를 만들지 않습니다.
- 소프트웨어 검증:
  - 운영 모드 실행 시험을 세 번 했습니다. 작업 폴더에서 두 번, GitHub에서 새로 받은 소스에서 한 번(의존성 없는 상태에서 약 2분) 모두 통과했습니다. 시험은 빈 자료 폴더와 빈 포트를 써서 시작 → 프로젝트·파일 생성 → 중지(포트 해제 확인) → 재시작 → 보존 확인 → 중지를 자동으로 합니다. 화면이 연결할 서버 주소가 빌드에 들어갔는지, 서버가 화면 주소에서 온 요청을 받는지도 확인합니다.
  - 새 소스 시험에서 문제 하나를 찾아 고쳤습니다. 첫 빌드가 스스로 만드는 파일 때문에 재시작 때마다 화면을 다시 빌드했습니다(7절).
  - 전체 선언 검사: 업스트림 단계(백엔드 형식 검사와 테스트 1,491개 통과, 11개 건너뜀, 이 네트워크에서 받을 수 없는 질량분석 어휘 때문에 2개 제외, 프론트엔드 테스트), GAID 단위 검사 11개, GeoAIDesk 실행기 점검, 운영 모드 실행 시험. 첫 실행에서는 다른 시험과 동시에 돌린 부하로 프론트엔드 편집기 테스트 2개가 시간 안에 화면을 찾지 못했고, 같은 테스트를 단독으로 세 번 돌려 모두 통과했습니다. 부하 없이 전체를 다시 돌렸을 때 모든 단계가 통과했습니다(백엔드 1,491개, 프론트엔드 887개, GAID 11개, 운영 모드 실행 시험). 이어서 완료 절차의 검사에서 같은 테스트가 다시 실패해 원인을 확인했습니다. 업스트림 원본 그대로도 전체 프론트엔드 테스트 6회 중 3회 실패하는 기존 불안정성이었고(지연 로딩되는 편집기를 1초만 기다림), 대기 시간을 4초로 늘린 뒤 8회 연속 통과했습니다.
  - Windows·macOS 점검은 GitHub CI 작업으로 추가했지만 아직 실행되지 않았습니다(작업 브랜치는 CI 대상이 아님).

## 5. 한계

- Linux에서만 실행했습니다. Windows 기본 환경과 macOS 설치는 미시험이며 WP10에서 확인합니다.
- 첫 시작은 업스트림 과학 스킬 목록을 최신판으로 받습니다. GeoAIDesk 스킬 묶음(skill_hub WP01 산출물)을 판과 해시로 고정해 받는 기능은 WP03 몫이며, 배포 설명서에는 "대기"로 적어 두었습니다.
- 화면의 제품 이름과 문구는 업스트림 그대로입니다(WP07). 실행기 메시지, 판 번호, 업데이트 알림 대상만 GeoAIDesk로 바꿨습니다.
- 모델 연결, 대화, 분석 작업은 시험하지 않았습니다. 유료 모델은 쓰지 않았습니다.
- 릴리스 절차는 아직 실제 릴리스로 시험하지 않았습니다. 판 표기를 붙이면 초안만 만들어지므로 공개 전에 사람이 확인할 수 있습니다.
- 공개 저장소의 이슈 기능이 꺼져 있어, 실행기 오류 메시지가 안내하는 문제 신고 주소가 지금은 열리지 않습니다(task 문서의 확인 항목).

## 7. 대체되었거나 실패한 시도

<details><summary>펼치기 — 3건</summary>

- 운영 모드에서도 업스트림처럼 매번 고정 패키지를 다시 설치했더니, 이 PC의 npm 판이 의존성 잠금 파일을 크게 다시 써서 소스가 수정 상태가 되었습니다. 그대로 두면 사용자가 다음 판으로 업데이트할 때 충돌하므로, 운영 모드는 잠금 파일 그대로 설치하고 잠금 파일이 바뀐 때만 다시 설치하도록 바꿨습니다(개발 모드는 업스트림 동작 유지).
- 화면 빌드 재사용 판단에 첫 빌드가 만드는 파일까지 넣어, 새 소스에서는 재시작마다 다시 빌드했습니다. 빌드 산출 파일을 판단에서 빼서 고쳤습니다.

- 업스트림 프론트엔드 테스트 하나(편집 중인 초안이 화면 전환 뒤에도 남는지 확인)가 무작위로 실패해 완료 검사를 막았습니다. 다시 돌려 통과시키는 대신 원본에서도 실패함을 확인하고 그 테스트의 대기 시간만 늘렸습니다.
