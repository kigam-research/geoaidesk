## 1. 요청한 것

> 남은 항목 중 정해야 하는 항목은 권장 방식으로 진행하자. 사용자가 직접 확인해야하는 부분과 관련해서는 유료 구독 모델 시험의 경우 3000번 시험용 앱을 사용하여라. 그리고 PU빠른 시험은 제외해도 된다. gaid-release proof#2를 제외하고는 직접 테스트 에이전트(GPT 6.1 sol high 워커)를 GAID 허브와 시스템을 모르는 이용자라고 간주한 뒤 테스트를 진행하게 하면 된다. gaid-zotero-web-fix는 인증서 문제를 이미 해결한 것으로 이해하고 있다. 웹 서재에도 논문을 추가해두었다. — 2026-10-22 요청

이 작업이 맡은 것은 gaid-backend의 남은 세 항목입니다.

1. 시험 운영 시작(gaid-backend#1 가): PC74 고정 서비스, 관리자 초대 코드, 검토용 허브의 Workflow 5건을 사용자가 정한 작성자로 옮기기
2. 허브 스킬 기록을 허브 서버로 옮기기(gaid-backend#3 가)
3. 시험 그룹보다 넓히기 전 HTTPS 적용(gaid-backend#2 가): 전환을 준비하고 문서로 남기며, HTTPS 없이 넓히지 않기

완료 기준: 연구자가 접속할 수 있는 고정 허브 서버와 관리자 초대 코드가 있고, 서버에 로그인한 연구자끼리 허브 스킬을 공유하며, HTTPS를 켜는 데 필요한 것이 준비되고 적혀 있습니다.

## 2. 수행한 것

1. 검토 앱과 겹치지 않게 PC74에 허브 서버 전용 위치와 데이터 폴더를 정하고, 재부팅 뒤에도 다시 뜨는 사용자 서비스로 띄웠습니다.
2. 관리자 초대 코드를 만들어 대화 탭으로 드렸습니다. 검토용 허브 기록은 시험 중인 검토 앱을 건드리지 않도록 복사본을 떠 두었습니다.
3. 허브 스킬 서랍이 Workflow와 같은 방식으로 저장 위치를 고르도록 고쳤습니다. 로그인하면 기관 서버, 아니면 자기 PC입니다. 서버 쪽 저장은 하위 작업이 맡았고 제가 합쳤습니다.
4. 허브 서버가 직접 HTTPS로 응답하거나 같은 PC의 프록시 뒤에서 돌 수 있게 했습니다. 연구자 GAID가 기관 내부 인증기관을 믿도록 설정 한 줄을 추가했습니다.
5. PC74에 내부 인증기관과 서버 인증서를 만들고, 운영 데이터와 분리한 임시 서버로 HTTPS 응답을 확인했습니다.

## 3. 결과

그림 없음: 화면 변화가 작고(검토 표시 한 줄), 결과는 서버 운영 상태와 시험 결과입니다.

### 3.1 허브 서버 시험 운영

- PC74에서 원내망 주소로 허브 서버가 돌고 있습니다. 컴퓨터를 다시 켜도 자동으로 다시 뜨고, 실패하면 다시 시작합니다.
- 서버 데이터, 기록, 백업은 검토 앱(GAID 화면)과 다른 폴더에 둡니다. 검토 앱은 바꾸지 않았습니다.
- 관리자 초대 코드는 seongin@kigam.re.kr 계정용이며 2026-10-29까지 한 번 쓸 수 있습니다.
- 검토용 허브의 Workflow 5건과 댓글·별 기록은 복사해 두었습니다. 관리자 계정이 생기면 모두 그 계정의 Workflow로 옮깁니다. 여러 가상 이름이 같은 Workflow에 남긴 별은 한 계정으로 합쳐져 별 수가 줄어듭니다.

### 3.2 허브 스킬 공유

서버에 로그인한 연구자는 이제 허브 스킬도 기관 서버에서 함께 봅니다.

1. 스킬을 올린 연구자만 새 판을 올릴 수 있습니다. 다른 연구자는 같은 이름으로 올릴 수 없습니다.
2. 라이선스를 확인할 수 없거나 재배포가 금지된 판은 올린 연구자에게만 보입니다. 서버가 계정마다 걸러서 보내므로 다른 연구자는 파일도 받을 수 없습니다.
3. 검토 기록에 계정 이름이 남고, 화면의 "이름 확인 안 됨" 표시가 사라집니다. 자기 PC 허브에서 표시 이름으로 남긴 검토에는 이 표시가 그대로 남습니다.
4. 올린 연구자는 자기 판을 "확인함"으로 바꿀 수 없습니다. 이 규칙은 서버가 직접 확인합니다.
5. 스킬 파일은 판마다 한 번만 저장되고 바꿀 수 없습니다. 설치할 때 해시와 파일 목록을 다시 확인합니다.
6. 기존 PC 허브의 스킬 기록도 Workflow처럼 서버로 옮길 수 있습니다. 검토용 허브에는 옮길 스킬이 없습니다.

|---|---|---|
| 고정 허브 서버와 관리자 초대 코드 | 충족 | 3.1, 4절 |
| Workflow 5건 이전 | 미충족(대기): 관리자 계정이 아직 없음 | 5절 |

| HTTPS 준비와 켜는 방법 | 충족(준비만, 켜지 않음) | 3.3 |

### 3.3 HTTPS를 켜는 데 필요한 것

시험 그룹보다 넓히기 전에 아래를 합니다. 저장된 자료를 바꾸지 않고 설정만 바꿉니다.

1. 서버: 준비해 둔 인증서 두 파일을 서비스 설정에 넣고 서비스를 다시 시작합니다. 그 뒤로 이 주소는 HTTPS로만 응답합니다.
2. 연구자 PC마다: 인증기관 파일 하나를 받아 두고, GAID 설정 파일에 그 위치를 한 줄 적고, GAID를 다시 시작합니다. 설정 → 서비스 → 기관 GAID 허브에서 주소를 `https://`로 바꾸고 한 번 다시 로그인합니다.
3. 서재 동기화 상태, 계정, Workflow와 스킬 기록은 그대로 이어집니다. 서버 식별자가 바뀌지 않기 때문입니다.
4. 인증서는 PC74의 지금 IP 주소에 묶여 있습니다. 주소가 바뀌면 인증서를 다시 만들어야 하므로, 넓히기 전에 고정 주소나 기관 도메인 이름을 정해 두는 편이 안전합니다. 기관 IT가 인증서를 주면 그것을 쓰고, 공인 인증서라면 연구자 PC 설정은 필요 없습니다.

인증기관 대신 기관 프록시를 쓰는 방법도 같은 문서에 적었습니다.

## 4. 검증

- 과학적 검증: 해당 없음(연구 결과가 아니라 운영 기반입니다).
- 소프트웨어 검증:
  - 실제 HTTP 허브 서버에 두 계정을 붙여 스킬 등록, 비공개 판 숨김, 별·댓글, 계정 검토, 자기 판 확인 거부, 이름 가로채기 거부, 다른 계정의 설치, 새 판 등록을 확인했습니다.
  - 서버 쪽 시험 52건(데이터베이스 2차 변경, 계정별 숨김, 파일 한 번 저장, 검토 규칙, 백업과 복원 확인, 스킬 가져오기)이 통과했습니다.
  - 내부 인증기관으로 만든 인증서로 실제 허브 서버에 HTTPS 로그인까지 되고, 인증기관 파일이 없으면 거부되고, HTTPS 포트에 일반 HTTP 요청은 실패함을 시험했습니다. 프록시 뒤에서 로그인 실패 제한이 연구자 주소별로 따로 세어짐도 확인했습니다.
  - PC74에서 준비한 인증서로 임시 서버를 띄워 원내망 주소로 HTTPS 응답, 일반 HTTP 거부, 인증기관 없이 접속 거부를 확인하고 지웠습니다.

  - 운영 서버: 원내망 주소로 상태 응답을 확인했습니다.

## 5. 한계

- Workflow 5건 이전은 관리자 계정이 생긴 뒤 합니다. 지금 검토 앱은 사용자 확인 시험 중이라 서버에 연결하지 않았습니다. 시험이 끝나면 허브에 검토 앱 연결을 요청합니다.
- 지금 시험 그룹은 원내 HTTP로 씁니다. 비밀번호, 로그인 열쇠, Workflow, 스킬, 서재 PDF가 암호화되지 않고 원내망을 지납니다. 넓히기 전에 3.3을 합니다.
- 서버를 로그인 상태로 쓰는 GAID의 설정 → 스킬 목록은 최근에 서버에서 받은 기록으로 "최신 판"을 보여 줍니다. 허브 화면을 한 번도 열지 않았으면 최신 판이 비어 보일 수 있습니다.
- 검토자 역할, 관리자 중지, 신고, GitHub 원본 비교는 다음 작업(gaid-hub-skills-2)입니다. 지금은 스킬을 볼 수 있는 계정이면 누구나 검토를 남깁니다. 검토 권한을 한 곳에서 판단하도록 만들어 두었습니다.
- 서버 데이터는 암호화해 저장하지 않습니다. 서버 폴더와 백업은 개인 연구 자료로 보호해야 합니다.
