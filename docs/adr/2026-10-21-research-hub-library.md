# ADR 2026-10-21: A hybrid personal library under "내 연구"; Zotero stays the source for Zotero items

Status: accepted 2026-10-21 (user chose the recommended option for all questions, added the hybrid requirement and
combined the layout drafts, gaid-research-hub). Context: reports/2026-10-21-gaid-research-hub §3.5–3.10, §6.

Superseded in part by [ADR 2026-10-24 GAID Connect/Workspace](2026-10-24-gaid-connect-workspace.md): decision 1’s place structure is replaced; 서재 is personal and opens from either place.

## Context

GAID has no reference library, bibliography or literature entry (inventory 2026-10-21): notebook entry types are
hypothesis/method/observation/decision/note, research notes have no citation field, hub authoring sources carry a
free-text DOI, the upstream literature skills (paper-lookup, citation-management, literature-review, pyzotero, …) are not
in the geo catalogue. The shared GAID hub runs on one institute server and identifies people only by a display name
(`X-GAID-User`, no accounts). Research notes are Markdown files and the file is the master (user decision 2026-10-18).

Three independent surveys (two oracle runs, two Claude runs supplied by the user) agree: researchers keep their reference
manager and writing tools; Zotero 10 (2026-08-17, latest 10.0.6) is the only realistic integration target (Local API
read on 7+, write on 10+ after a user-granted local key; Web API v3 with per-user keys; no headless Zotero); PDF
reading, citation graphs, generic discovery and notebook-style document chat are better served by existing tools.
Many intended GAID users do not use Zotero or Obsidian and work only with web search and PDF files (user, 2026-10-21).

## Decision

1. **Information architecture.** Personal material (library, my papers, ideas) lives under "내 연구"; its home becomes a
   research dashboard (this week's tasks, new papers, projects). The GAID hub stays the institute sharing place
   (Workflows) and gains a paper-centred view ("논문으로 찾기": a published paper and the Workflows made from it). Private
   PDFs, manuscripts, reviews and ideas never go to the shared hub.
2. **One personal library, two item sources.** Every researcher has one GAID library. An item is either
   - *Zotero-linked*: mirrored read-only from Zotero (PC: Local API of the running Zotero; server: the researcher's Zotero
     Web API key). Zotero is the source of its metadata, PDFs and annotations; GAID opens the item/page in Zotero to edit.
   - *GAID-managed*: added in GAID (PDF drop with DOI/title detection and Crossref/OpenAlex/KCI metadata confirmed by the
     researcher, DOI/URL paste, "서재에 넣기" on agent search results, BibTeX/RIS/CSL-JSON import). GAID is its source;
     PDFs sit in the researcher's personal GAID storage. "Zotero로 보내기" moves it to Zotero; the GAID item id, citations
     and links stay valid.
   Every downstream feature (project literature, page-anchored answers, note citations, comparison tables, paper →
   Workflow, manuscripts) works on the GAID item id and is source-agnostic. GAID-managed items are deliberately light:
   no browser capture button, no Word plugin, no style editor.
3. **Zotero integration rules.** Official APIs only (never read `zotero.sqlite`; Zotero 10 changed it to WAL + separate
   FTS DB). Incremental sync per Zotero source and library (`since` versions; Local API versions are per
   `Zotero-Server-ID` and never compared with Web API versions). Write-back only after the researcher confirms, and only:
   add to a "GAID 수집함" collection, add a child note linking the GAID research note, add tags. No metadata edits, no
   annotation writes (undocumented in both APIs). Citation keys come from Zotero's own field (Zotero 8+, generated by
   Better BibTeX); when it is empty GAID assigns a stable author+year alias kept across syncs. Internal links use the
   Zotero item key, the citation key is an alias. GAID does not depend on Better BibTeX's HTTP export, JSON-RPC or CAYW:
   on 2026-10-21 BBT 9.0.71 still declared Zotero 8/9-beta compatibility and had open Zotero 10 issues (#3602 slowdown,
   #3626 empty CAYW on 10.0.6).
4. **Storage.** Library state is user-level (under the GAID agent/user data directory, next to the hub authoring store),
   with an owner field from day one; a project stores only references to items/collections. Notes keep the file-master
   rule and cite with Pandoc syntax (`[@key, p. 12]`); a write/edit hook flags citation keys not in the library, like the
   Markdown image-link check. Evidence anchors (item, attachment, page, figure label, optional Zotero annotation key,
   quote, file hash, verified) generalise the hub authoring `Anchor`; anchors are rechecked when the PDF is reopened.
   PDFs are referenced, never copied to the shared hub.
5. **Where it runs first.** Phase 1 runs on the researcher's own GAID (PC). The institute server hosts personal
   libraries only after accounts, per-user storage and per-user Zotero keys exist; the user chose to build them right
   after the phase-1 pilot, before "내 논문" (2026-10-21).
7. **Default model for unpublished material.** Work on unpublished manuscripts, review comments and ideas defaults to
   the institute-internal model connected to GAID; the researcher can switch, and GAID says so before sending such
   material to an external provider (user decision 2026-10-21).
8. **Library screen.** First screen = large search, "이번 주" and new papers (draft 다안); the list is a table (나안)
   and the selected paper opens the detail pane with "내 연구에서 쓰인 곳" (가안) (user decision 2026-10-21).
6. **Citations the agent may write** are library items or DOIs whose metadata resolved; anything else is shown as
   "확인 안 됨". Paper text is untrusted input (prompt injection); literature-reading work runs without file writes or
   outbound connections beyond the configured services.

## Alternatives considered

- *Everything inside the GAID hub* (private tabs next to shared Workflows): one entry point, but private and shared data
  in one place on a server without accounts. Rejected.
- *A new top-level "서재" place*: visible, but separates manuscripts from projects and adds a third place. Rejected.
- *Zotero as the only source, GAID offers import only* (first proposal): fails researchers who use only web search and
  PDFs. Replaced by decision 2.
- *GAID as a full second reference manager*: competes with Zotero on capture, Word citation and PDF reading. Rejected.
- *Full two-way Zotero sync*: conflict handling, 50-object batches, no annotation writes, group permissions. Rejected.
- *Institute-server library before accounts*: display names cannot protect unpublished manuscripts. Rejected.

## Consequences

- New contracts under `web/src/geo/contracts/` (library item/source, evidence anchor, project literature) and a server
  module under `server/src/geo/` are needed before UI work; the hub authoring `Anchor` should move onto the shared type.
- The geo catalogue must offer the upstream literature skills (paper-lookup, citation-management, literature-review,
  pyzotero) or GAID equivalents; `pyzotero` is default-disabled today.
- Open checks: Zotero Web API JSON carries `citationKey`; GAID in WSL reaching Windows Zotero on `localhost:23119`;
  Better BibTeX on Zotero 10.0.6; arXiv API reachability (timed out from PC74 on 2026-10-21; Zotero Web API, Crossref,
  OpenAlex, KCI, ORCID reachable; Semantic Scholar keyless pool returned 429).
